# Authenticate `/usr` as the release artifact and deliver configuration by signed confext

## Context

DES-0006 originally authenticated a complete root filesystem, including a
flattened `/etc`, inside the signed release artifact. [DES-0006
C-013](../designs/0006-storage-layout-and-encryption/review.md) challenged that
scope as never having been examined: C-007 had challenged the root *format* and
left the root *scope* unstated. The systemd/UAPI stack selected under
[ADR-0001](0001-systemd-first.md) is built around authenticating `/usr` only,
with `/etc`, `/var` and `/home` writable, on the rationale that a hermetic OS is
definable inside `/usr` and that trees outside it are regenerated by
`systemd-sysusers` and `systemd-tmpfiles` rather than shipped. ParticleOS, named
by RES-0001 as the closest executable reference for the default candidate, makes
the `/usr`-only choice.

The full-root scope rested on one reason: authenticating exact flattened `/etc`
inside the release artifact. That reason does not survive contact with the
accepted requirements. Configuration integrity is required to be deterministic
and attributable, with cryptographic authentication welcome but not the floor,
and a signed confext under a strict image policy exceeds that floor without
placing configuration inside the root image.

**This decision was ruled and accepted 2026-08-11** and has governed every
subsequent plan; this ADR records it in the authoritative form rather than
leaving it in a design review. It has since been exercised by PLN-0001 and
PLN-0002, whose evidence appears under review triggers below.

## Decision

The authenticated release artifact is **`/usr`**, with its dm-verity pair and a
signed UKI carrying the root hash. It is not a complete root.

Configuration is delivered **exclusively by signed confexts**. The real `/etc`
holds nothing durable and is regenerated at boot by `systemd-tmpfiles` and
`systemd-sysusers`; durable content found in `/etc` is a fault to report, not
state to preserve.

Confext mutable modes are foreclosed. `Mutable=` write-routing through
`/var/lib/extensions.mutable/` is the unattributed mutable administrator layer
SYS-123 forbids, so **`Mutable=disabled` with `image_policy_confext_strict` is
required, not preferred**.

Every confext is a release-owned artifact and inherits the full SYS-123
lifecycle: exact content identity, base compatibility, authorization,
qualification, activation ordering, health, rollback, retention, and effective
deployment status. [DES-0005's accepted
amendment](../designs/0005-fleet-intent-and-configuration/README.md) settles
those obligations as a set of confexts split by disjoint path ownership, base
compatibility as a level guard rather than an identity binding, per-confext
required/optional failure policy authored in the fleet inventory, and retention
by reference count.

**No requirement is amended.** SYS-049 requires read-only, authenticated release
root *content* bound to an identity carried by the boot artifact, not a
root-scoped filesystem, and its acceptance evidence already enumerates
configuration beside root, Verity and UKI. SYS-090 likewise treats configuration
as a distinct deployment-set member. G1's requirement set is untouched.

**This ADR decides scope, not mechanism.** The `/usr` filesystem format stays
open under DES-0006 C-007. The concrete `/etc` path carve, the confext build
tooling, and the delivery location for a separately delivered confext are
candidate fixtures owned by DES-0005 and open under `S-004`; nothing built in
PLN-0002 promotes them.

## Alternatives considered

### Whole read-only root with flattened `/etc` inside the artifact

Rejected, and rejected as a fork rather than a correction: ChromeOS and Android
both ship a whole read-only rootfs beside a separate stateful partition at very
large scale, so the model is field-proven and the question was never whether it
works. It was whether NeutrinOS's specific reason for it survived its cost. The
cost is that every mutable path must be projected out of state and every `/etc`
writer becomes an unsupported class — the unresolved C-002/C-006 debt — bought
against an integrity increment over `/usr`-only that was never stated or
measured. It also puts NeutrinOS off the path its chosen mechanisms are designed
and tested for, so upstream defaults, `systemd-sysext` facilities and
ParticleOS's exercised repart definitions stop being reusable and become work.

### Confext mutable modes for administrator overrides

Rejected under SYS-123 as an unattributed mutable administrator layer. This is a
consequence of the decision rather than an independent option, and it is
recorded because `Mutable=` is available and would otherwise look like a
convenience.

### Keeping the ruling in the design review

Rejected. The ruling is architecture and binds every plan since 2026-08-11,
while `AGENTS.md` classifies designs as arguments and reviews as
non-authoritative. Leaving an accepted architectural decision in a document
class defined as non-authoritative is the defect this ADR closes.

## Consequences

### Benefits

- NeutrinOS runs on the path its selected mechanisms are designed and tested
  for; upstream defaults and ParticleOS's repart definitions stay reusable.
- The `/etc`-writer exception class disappears as a design obligation.
- Configuration gains an independent authorization and rollback identity rather
  than riding inside the release artifact's.
- Release artifact and configuration can be qualified and replaced on separate
  schedules.

### Costs and constraints

- Every confext carries the full SYS-123 lifecycle. Configuration delivery is
  now a release-engineering surface, not a file copy.
- `Mutable=disabled` and `image_policy_confext_strict` are mandatory, so an
  operator override mechanism must be designed rather than assumed.
- Per-machine identity cannot live in `/etc` and its sourcing is constrained;
  this passes to `L-003`.
- The unqualified-configuration test path conflicts with
  `image_policy_confext_strict` and is open under `C-002`.

### Accepted risks

- **Early boot is the residual risk and the one respect in which `/usr`-only is
  weaker than full-root.** The root partition is unauthenticated state, so
  anything read before `/usr` is verified — `fstab`, `crypttab`, initrd-stage
  configuration — falls outside the integrity boundary. Upstream's answers are
  the signed UKI command line and
  `systemd-confext-initrd`/`systemd-confext-sysroot`, exercised in production by
  ParticleOS.
- A `/usr`-only layout concentrates trust in the UKI and its command line, which
  makes the command-line ruling under DES-0006 a security surface rather than a
  configuration preference.
- Configuration integrity now depends on confext signature enforcement being a
  real gate. See the review triggers.

## Validation and review triggers

Evidence produced since the ruling, none of which changes it:

- **PLN-0002-01 exercised early boot** rather than assuming it; the stop-gate
  was not triggered
  ([record](../project/spike-early-boot-record.md)).
- **Confext signature enforcement is closed and registered.**
  `--image-policy=root=signed` applied as a unit drop-in admits the enrolled
  signer and refuses the valid-but-unenrolled one; `T4-CONFEXT-001` measures the
  2x2 and is verified failure-sensitive
  ([check updates](../project/slice-check-updates.md)).
- **`/usr` verity signature enforcement is not closed.** An untrusted `/usr`
  verity signer does not stop the boot: `systemd-veritysetup` retries without the
  signature and reports success, so upstream's enforcement point is the TPM
  unseal rather than the mount. `systemd.image_policy=usr=signed` is a structural
  predicate, not an enforcement mechanism, and must not be cited as one. Open
  under `S-005`.
- **PLN-0002 measured eight fail-open instances across this slice's mechanisms**,
  including a refused confext that reported `Finished` and left the machine
  unconfigured. A successful boot is not a statement about the artifact
  ([substitution records](../project/artifact-substitution-records.md)).

Revisit this decision when:

- an integrity delta against `/usr`-only scope is stated and measured, rather
  than assumed, showing what an attacker or fault can do that full-root would
  prevent;
- early-boot integrity cannot be closed by the signed UKI command line and the
  initrd confext path, leaving the unauthenticated root a live exposure;
- per-machine identity sourcing under `L-003` cannot be satisfied without durable
  `/etc`;
- SYS-123's lifecycle obligations on every confext prove more expensive in
  operation than the `/etc`-writer exception class they replaced; or
- an operator override requirement emerges that `Mutable=disabled` cannot serve
  and no alternative mechanism satisfies.
